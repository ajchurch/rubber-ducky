# B3. Discover 3 proactive security implementations in practice.

## 1) Endpoint Detection and Response (EDR) / Antiviruses
Software installed on laptops, servers, and phones that continuously monitors for malicious behavior and blocks threats. Modern EDR tools like CrowdStrike Falcon or Microsoft Defender go beyond traditional antivirus by using behavioral analysis to catch novel attacks.

CrowdStrike Falcon famously catches attack chains like a user opening a phishing attachment that spawns PowerShell, which then reaches out to a command and control server. None of those steps alone is necessarily malicious, PowerShell is a legitimate admin tool, but the sequence of a Word document spawning PowerShell calling an unknown IP is the signature of a real attack, and EDR catches the pattern even when no individual file matches a known virus. 

## 2) Regular Backups and Disaster Recovery Planning
Backups are the safety net that makes ransomware, hardware failure, accidental deletion, and natural disasters survivable rather than fatal, allowing operations to be restored quickly. 

Nowadays many companies use a 3,2,1 rule to their disaster recovery planning. This consists of:
* 3 copies of your data (the original plus two backups)
* 2 different storage media (e.g., disk and cloud)
* 1 copy offsite or air-gapped

However more recently the rule is more close to 3,2,1,1,0 which adds the above and also one immutable or offline copy and zero errors after verification, specifically to defend against ransomware that increasingly targets backups themselves.

## 3) Zero Trust Architecture
A security model built on 'never trust, always verify' where instead of assuming anyone inside the corporate network is safe, every access request is authenticated, authorised, and continuously validated. 

Google's BeyondCorp is a well known real world implementation

When a Google employee tries to access an internal application, the request does not go directly to the app, it flows through several coordinated components:
* Access Proxy - A gateway that sits in front of every internal application and intercepts every request. Nothing reaches the app without going through the proxy first.
* Device Inventory Service - Continuously tracks every known device, its configuration, patch level, and security posture. Unmanaged personal devices typically get limited or no access.
* Trust Inferrer - Continuously analyses device state and assigns a 'trust tier'. A fully managed, fully patched Google laptop earns the highest tier whereas a slightly outdated one drops to a lower tier with reduced access.
* Access Control Engine (Policy Engine) - The decision-making brain. It evaluates the user identity, the device's trust tier, the resource being requested, and contextual signals like location and time, then either grants, denies, or steps up authentication for the request.
* Single Sign On (SSO) & MFA - Identity is verified once with strong factors typically through hardware security keys in Google's sense, and reused across applications.
